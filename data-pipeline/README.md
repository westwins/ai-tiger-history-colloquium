# 아카이브 수집과 역사자료 DB 파일럿

2026-11-06에 공개 원자료를 실제 수집하고 정규화·SQL 적재를 검증한 작업입니다. 운영 앱의 `trc_*` 테이블을 수정하지 않고, Oracle의 별도 MariaDB 데이터베이스 `trc_research_staging`을 사용했습니다.

## 현재 확보·검증한 자료

| 출처 | 수집 결과 | 집계 단위 | 공간 정보 |
|---|---:|---|---|
| Freire 외(2019) 연구 데이터 | 2,398건 × 원본 59개 변수 | 출처 내 인물 기록 | 최대 6개 장소, 장소별 정확도 |
| MMDH 박물관의 공개 Excel 내보내기 | 3,216건 | 출처 내 사망·강제실종 인물 목록 | 원문 지역·도시·코무나, 좌표 미제공 |
| 제주4·3평화재단 공개 유적 소개 | 25곳 | 소개된 유적 | 원문 지역 분류, 좌표 미제공 |

두 칠레 명부는 겹칩니다. 총 5,639개 **출처별 기록**을 서로 다른 자료군으로 적재했으며, 서로 다른 희생자 5,639명을 확보했다는 뜻이 아닙니다. 제주 25곳도 제주 희생자 수나 전수 유적 수가 아닙니다.

Oracle 검증 결과는 `output/oracle-staging-verification.json`에 있습니다. 동일 SQL을 두 번 실행해도 행 수가 증가하지 않았고, 운영 앱의 기존 사건 테이블 2,116건은 유지됐습니다. 7,395개의 장소 관찰 행에는 좌표 없는 행도 포함됩니다.

## 기존 칠레 화면이 편중돼 보이는 이유

- 기존 수집기는 `latitude_1` 또는 `longitude_1`이 없으면 인물 전체를 버렸습니다. 원자료 2,398명 중 289명이 이 때문에 제외됐습니다.
- 그 289명 중 117명은 두 번째 이후 장소에 좌표가 있습니다. 어느 장소에도 좌표가 없는 172명도 새 DB에는 남깁니다. 첫 장소와 이후 장소의 역할을 바꿔 표시하지 않습니다.
- 원자료의 시작 날짜는 일 단위 2,232건, 월 단위만 알려진 57건, 미상 109건입니다. 월을 아는 기록을 날짜 미상과 구분합니다. 월 첫날은 관찰된 사건일이 아닌 구간의 하한입니다.
- 1973년은 일·월 단위 원자료를 합쳐 1,274건입니다. 기존 API는 좌표와 일 단위 날짜를 모두 가진 1,188건만 그해에 집계합니다. 데이터 저자도 쿠데타 직후 초기 집중을 설명하지만, 수집 자료의 범위와 역사적 피해의 모집단을 구별해야 합니다.
- 1974년 이후 이키케·비냐델마르·라우타로·파랄 등의 기록도 있습니다. 산티아고 대표 좌표 하나에는 첫 장소 기록 265개가 겹칩니다. 단일 점의 시각적 크기만으로 전체 분포를 판단하기 어렵습니다.
- MMDH 자료도 수도권 이외에 비오비오·로스라고스·아라우카니아·발파라이소 등 여러 지역을 포함합니다. `RM Metropolitana`는 산티아고 **시**와 동일하지 않습니다.

대조 결과와 재현 가능한 집계는 `output/chile-quality.json`, `output/mmdh-quality.json`, `research-queries.sql`에 있습니다. 대화형 검토 화면은 `output/coverage-review.html`입니다.

## 우선 수집 대상

전체 등록부는 `sources.json`입니다. API가 있다고 가정하거나 기록번호를 전수 대입하지 않고, 실제 제공되는 일괄 파일과 공개 링크를 먼저 확인했습니다.

1. **칠레 MMDH 희생자 목록**: 공개 목록의 `Descargar Excel` 링크를 확인해 일괄 다운로드했습니다. 파일 이름은 Excel이지만 실제 내용은 HTML 표이므로 헤더를 확인한 전용 파서로 읽습니다. 3,216건을 확보했습니다. 원자료의 `Fecha Detención/Muerte`는 체포일/사망일을 혼용하므로 확정된 사망일이라고 바꾸지 않습니다. 00으로 표시된 날짜 일부, 스페인어 월 표기, 연도만 있는 값을 정밀도별 구간으로 보존했습니다. `-1982` 1건과 1991년 표기 1건은 원문 재검토 대상입니다. 지역의 오기·옛 구분도 자동 정정하지 않습니다.
2. **제주4·3아카이브**: 재단에서 실제 안내한 `http://43archives.or.kr/main.do`는 정상 연결됩니다. HTTPS 접속 시간초과와 아카이브 전체의 장애를 구별해야 합니다. 메인에서 연결된 통합검색·시대별·지역별·자료현황을 확인했습니다. `record_no=5813`의 2003 진상조사보고서, `record_no=5814`의 2019 추가진상조사보고서 I의 공개 기술정보와 식별번호도 확인했습니다. 기록물 생산일을 피해 발생일로 바꾸지 않습니다.
3. **제주4·3 진상조사·마을별 피해조사**: 평화재단은 12개면 165개리 조사와 읍면별 보고서 13권 작성을 명시합니다. 이 보고서군을 우선 확보해 사건 일자·마을·인원·명부·증언의 관계를 쪽 단위로 추출하는 것이 제주 데이터 확장에 중요합니다. 공개 원본 파일 및 기계 판독본의 일괄 제공 가능 여부를 확인해야 합니다.
4. **제주 공개 유적·위패 검색**: 유적 소개는 공간 레이어용, 위패 검색은 위패 위치 확인용입니다. 위패 검색이 사건일·희생 장소의 전수 DB라고 가정하지 않습니다. 성명을 전수 대입하는 방식 대신 공개 명부 또는 기관 제공 파일 확보를 우선합니다. 비공개 유족·신청·보상 정보는 대상이 아닙니다.
5. **칠레 INDH·MMDH 문서, 국가기록원**: 보고서 판본·권·쪽, 기록물 관리번호, 공개 여부를 인물·사건의 근거에 연결할 두 번째 자료군입니다. 문서 수와 희생자 수를 혼동하지 않습니다.

제공기관에 일괄 자료를 요청할 경우에는 공개 가능한 식별자, 자료 제목/유형, 원문 위치, 사건 일자와 그 정밀도, 장소 원문과 좌표 근거, 인정/조사 기준, 갱신 기준일, 재이용 조건을 확인하는 것이 유용합니다. 기관에 메시지를 보내지는 않았습니다.

## 구조와 재현

`pipeline.py`는 Python 표준 라이브러리만 사용합니다. 수집한 바이트는 SHA-256 이름으로 보존하고, 수집 시각·최종 URL·HTTP 상태·ETag·robots 결과를 `raw/fetch-log.jsonl`에 기록합니다. 허용된 출처 호스트와 실제 관찰된 링크만 대상으로 삼으며, 호스트별 요청 간격과 응답 크기·재시도 한도를 둡니다. robots 확인 실패는 404/410 이외에는 중단합니다.

```sh
python3 pipeline.py fetch-chile
python3 pipeline.py prepare --legacy-json raw/live-chile.json
python3 pipeline.py probe chile-mmdh-victims jeju43-archive jeju43-sites
python3 pipeline.py fetch-discovered chile-mmdh-victims 'https://interactivos.museodelamemoria.cl/victims/?page_id=7836&exportar_entradas_to=true'
python3 pipeline.py prepare-mmdh
python3 pipeline.py prepare-jeju-sites
python3 build_review.py
python3 -m unittest -v test_pipeline.py
```

`prepare`의 `--legacy-json`은 선택 옵션입니다. 기존 앱 대조 자료가 없어도 전체 원자료를 적재할 수 있습니다. `probe`는 출처당 첫 페이지를 점검하는 기능이며, 아카이브 전체 수집 완료를 뜻하지 않습니다. `fetch-discovered`는 저장된 probe에 존재하는 실제 링크만 받습니다. 수집 파일의 재배포 허용 여부는 공개 열람 가능 여부와 별도로 확인해야 합니다.

로컬 검토 DB는 `output/research.sqlite3`입니다. MariaDB용 스키마는 `schema.mariadb.sql`, 생성된 출처별 입력문은 `output/*-import.mariadb.sql`입니다. `validate_oracle_staging.py`는 서버에서 시험 DB를 만들고 입력·재입력·운영 건수 보존을 확인합니다. 운영 반영용 자동 명령은 아닙니다.

- `hist_source`: 출처와 포함 범위
- `hist_snapshot`: 파일 해시·수집 정보·파서 버전
- `hist_record`: 출처 내 기록 식별자·유형·날짜 구간·원본 필드
- `hist_place`: 한 기록의 여러 장소, 원문 지명·좌표·정확도·장소 역할

같은 원본과 같은 파서 버전의 재실행은 중복되지 않습니다. 파서가 바뀌면 새 버전을 남길 수 있습니다. 분석 SQL은 출처별 최신 스냅샷을 선택해야 합니다. MMDH 내보내기에는 안정적인 인물 ID가 없어 내용 지문으로 기록 키를 만들었으며, 그 키를 실제 인물 ID로 간주하지 않습니다.

## 이어서 구현할 범위

현재 완성된 것은 두 칠레 자료군과 제주 공개 유적 소개의 수집·정규화·적재 파일럿입니다. 제주 희생자 전수 명부, 보고서 전체 OCR, 문서 쪽 단위 구조화, 출처 간 인물 일치 판정, 지명 사전과 행정구역 변동 대조, 대규모 수집 작업의 중단/재개 큐, 운영 앱의 신규 데이터 전환은 완료했습니다.

확장 순서는 **제주 보고서·명부 확보 → 쪽/표 단위 추출과 검수 → 인물·사건·장소의 출처별 주장 연결 → 검수한 자료의 공개 뷰 → 기존 6단계 앱 연결**이 적절합니다. 지도는 같은 좌표의 기록 수, 좌표 정밀도, 위치 미상 건수를 함께 보여야 합니다. 인물·문서 수를 피해 사건 수로 바꾸는 집계는 별도의 사건 연결 검토 뒤에 수행해야 합니다.

## 운영 반영 완료

추가로 `collect_map_sources.py`가 공식 지역별 공개 API의 13개 지역을 수집해 47개 공개 유적을 확보했습니다. `build_geography.py`는 칠레의 2020 참고 행정경계(geoBoundaries / BCN / OCHA ROLAC, CC BY 3.0 IGO)와 OSM 지역·유적 참고 위치를 구성합니다. 유적은 피해자 수와 구별하며, 원문의 등록일·수정일을 사건일로 사용하지 않습니다.

4개 자료군의 `hist_*` 테이블을 운영 `trc_archive` DB에 추가하고 지도에 연결했습니다. 기존 테이블은 유지했습니다. 지역 대표점과 현대 유적 참고 위치는 `backend/geography.json`에 별도로 보존하며, 원자료의 위경도를 덮어쓰지 않습니다. 제주 희생자 전수 명부·보고서 전체 OCR·개인/사건 연결의 검수는 완료된 것으로 표시하지 않습니다.
